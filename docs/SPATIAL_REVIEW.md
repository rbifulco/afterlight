# Afterlight spatial review integration

## Scope and access

The requested integration adds SDK 0.7.0 to the existing Three.js 0.180 project.
The dedicated capture document registers only the objects listed below. The
ordinary document retains its renderer, controls, sound, and animation loop;
neither the SDK nor capture module is in its import graph. The shared builders
only return additional references to their already-created vehicles/residents.

The integration enables the official Alterno origin,
`https://spatial-review.alterno.dev`, plus the SDK's same-origin access. It does
not enable other loopback origins. Registered roots expose descendant geometry,
materials, textures, source references, image URL strings, and transferable image
bytes. No application state, DOM, cookies, or storage is registered. Source
textures use repository-owned `/assets/` paths or generated canvases; no signed
or credential-bearing URLs were found in these builders. SDK readiness announces
build identity, counts, capabilities, and limits to the parent/opener.

Static discovery keeps review code out of the ordinary page. The production
server and Sites Worker permit the official editor to fetch only the discovery
document via CORS. Existing framing headers were not changed (the source server
and Worker do not set anti-framing headers). A hosting platform may add headers;
that requires deployment verification. No deployment or public-site change was
performed.

## Local workflow

1. Run `npm ci`, `npm run build`, and `npm run serve`.
2. Enter `http://localhost:4173/` in `https://spatial-review.alterno.dev`.
3. The editor discovers `http://localhost:4173/spatial-review.html` through
   `http://localhost:4173/.well-known/spatial-review.json`.
4. Keep the capture page alive for on-demand geometry and texture requests.
5. Export feedback from the editor and apply it to the authoritative source
   below. The adapter does not automatically apply feedback to the city.
6. Rebuild and reload both capture and editor after source changes. Builds hash
   source, assets, and the lockfile, so modified source gets a new review build ID.
   Restart the Vite development server after source changes to refresh that ID.

Browser local-network access restrictions may require the browser's local-network
permission. If embedding is blocked by browser or hosting policy, use the editor's
popup capture workflow. Neither path has been accepted in a real browser in this
change.

## Inventory and source mapping

The fixed snapshot uses time zero, the city's seeded procedural construction,
and initial resident/courier placement. There is no animation loop, audio,
WebGL context, or weather randomness on the capture page. Actors and assets use
the same stable semantic ID; differently colored vehicle/resident variants have
separate assets. Units and axes are unchanged: metres, Three.js Y-up. Scene
feedback must be applied to the original source pivot, accounting for the
captured actor transform; bounds centers are not placement pivots.

| IDs | Source | Review scope |
| --- | --- | --- |
| `district-context` | `src/city.js#buildCity` | Batched architecture, signs, train, distant traffic |
| `street-life-context` | `src/street-life.js#buildStreetLife` | Batched interiors, equipment, repair arm, screens |
| `road` | `src/main.js#street` | Original dimensions and placement; approximate asphalt appearance |
| `taxi`, `service-van`, `passing-sedan` | `src/vehicles.js#taxi`, `#serviceVan`, `#movingCar` | Individual vehicle placement and construction |
| `parked-sedan`, `west-scooter`, `noodle-bar-scooter`, `east-scooter` | `src/vehicles.js#buildVehicles` | Remaining `add()` calls in source order |
| `courier` | `src/main.js#character`; model from `scripts/build-humans.py` | Initial model pose and placement |
| Eight `resident-*` actors | `src/people.js`, exact human-readable resident ID | Actual source skeleton posed at time zero and baked into geometry |
| `resident-props` | `src/people.js#buildPeople` | Shared umbrella instances, cups, chopstick |
| `service-android` | `src/main.js#android`; `scripts/build-android.py` | Android construction and placement |

Materials and texture slots map to the corresponding factory above. Vehicle
paint/glass and decals are authored in `buildVehicles`; resident clothing maps
to `buildPeople` plus `src/main.js` cloth setup; city surfaces and generated sign
canvases map to `buildCity`; hologram artwork maps to `buildStreetLife` and
`src/hologram.js`. Asset component suffixes generated by the SDK identify nodes
within that factory's exported hierarchy, not independent source symbols.

## Representation limits

- City geometry is merged across the district by material in the source.
  Architecture and shop equipment therefore remain coarse context actors.
  Individual-building or individual-furniture movement is not supported by this
  first integration. Their source factories remain the place to apply feedback.
- Resident poses are baked because SDK 0.7.0 serializes raw geometry rather than
  skin deformation. This is a snapshot, not editable character animation. The
  courier uses its initial model pose rather than the renderer's idle motion.
- Reflective asphalt uses a static material approximation. Holograms retain their
  artwork texture and tint in a standard transparent material, but lose custom
  scanlines, additive shading, vertex displacement, and time distortion.
- Shader-injected road wear, window vertex colors, environment lighting,
  bloom, fog, ambient occlusion, reflections, rain, steam, runoff, fabric/wind
  effects from `atmosphere.js`, and sound are not faithfully represented.
  Appearance review of these effects is unsupported; use the live website.
- No Experience sequences are exported. Afterlight's camera follows interactive
  walking/orbit input; there is no authored camera journey to register. Navigation
  point count is zero.
- The current editor's progressive geometry path is the intended consumer.
  A full scene-profile legacy catalog measured about 52.8 MB of JSON in a
  headless smoke check; older complete-catalog consumers are not an acceptance
  target. Progressive metadata remains below 100 KB. The per-asset geometry
  ceiling is 64 MiB; the SDK bounds request concurrency and queued work.

## Verification

`npm test` passes nine tests, including the existing navigation/batching checks.
The new tests construct the complete capture inventory, negotiate progressive
capture, request district/shop/taxi/resident assets within the geometry budget,
reject an untrusted editor, detach the bridge, verify discovery URLs and CORS,
and compare baked vertices with actual posed GLB vertices. Capture smoke tests
mock canvas/image APIs: they do not establish visual fidelity, image decoding,
or successful browser texture-byte transport.

`npm run build:sites` builds both entrypoints and stages the Worker and static
assets, including the hidden discovery directory. The SDK is isolated to the
capture entrypoint. Vite reports a shared Three.js chunk above its default size
warning threshold.

Local HTTP checks returned 200 for the ordinary page, capture page, and static
discovery. Discovery returned the official-editor CORS header, and a representative
`/assets/concrete.png` response returned `Content-Type: image/png`. The staged
Sites artifact contains the discovery document. These checks do not establish
the deployed host's behavior or browser texture transfer.

Still unverified: ordinary-page visual/interaction comparison, real editor
discovery from the ordinary URL, representative Scene and Asset appearance,
texture readiness and byte transfer, feedback export/source-application/refresh,
and hosted framing/discovery responses. No end-to-end browser acceptance or
production deployment is claimed.
